Comment sortir du blocage de Microsoft (Outlook et Hotmail)

Ce que signifient les erreurs S3150, 5.7.511, 4.7.650 et 5.7.515 d'Outlook, comment savoir pourquoi vous êtes bloqué et comment demander le retrait étape par étape.

Pourquoi Microsoft est le plus difficile

Outlook.com, Hotmail, Live et MSN utilisent leur propre filtre et leur propre liste de blocage, avec des critères que Microsoft ne publie pas. Contrairement à Gmail, il ne montre pas votre réputation dans un tableau de bord : vous le découvrez quand vos emails commencent à rebondir ou à arriver dans le courrier indésirable.

La bonne nouvelle : presque tous les blocages de Microsoft se règlent si vous trouvez la cause avant de demander le retrait. Si vous demandez à être retiré sans rien corriger, vous revenez sur la liste en quelques jours.

Identifiez votre erreur

Lisez le rebond complet. Microsoft inclut presque toujours un code entre parenthèses qui indique ce qui se passe :

  • 550 5.7.1 … (S3150) ou (S3140) : votre IP est sur la liste de blocage de Microsoft. C'est le cas le plus fréquent.
  • 550 5.7.511 Access denied, banned sender : blocage plus grave. Le message vous demande lui-même de transférer le rebond à delist@microsoft.com.
  • 451 4.7.650 : ce n'est pas un blocage mais un ralentissement temporaire lié à la réputation. Microsoft accepte moins de vos emails jusqu'à ce que la réputation s'améliore.
  • 550 5.7.515 : votre domaine ne respecte pas les exigences d'authentification pour les envois en masse (SPF, DKIM et DMARC). Une demande de retrait n'y changera rien : il faut configurer le domaine.

Si le message ne vous parle pas, collez-le dans le traducteur de rebonds pour savoir ce qu'il signifie et quoi faire.

Avant de demander le retrait, corrigez la cause

Microsoft examine votre IP quand vous demandez le retrait. S'il voit toujours le même problème, il vous dira qu'il ne peut pas vous retirer. Vérifiez d'abord :

  • Authentification : SPF, DKIM et DMARC corrects et alignés avec le domaine de l'expéditeur. Vérifiez-le avec Exigences de Gmail, Yahoo et Microsoft.
  • DNS inverse (PTR) de l'IP avec un nom propre, non générique, qui renvoie vers la même IP. Vérifiez-le dans Informations sur une IP.
  • Qualité de la liste : supprimez les adresses qui rebondissent, les contacts inactifs depuis plus de 6 à 12 mois et toute personne qui ne vous a pas donné son accord. Les pièges à spam de Microsoft se cachent dans les listes anciennes ou achetées.
  • Plaintes : si beaucoup d'utilisateurs signalent vos emails comme spam, Microsoft vous bloque même si tout est correct techniquement.
  • Volume : un pic soudain depuis une IP nouvelle ou froide est l'une des causes les plus courantes.

Inscrivez-vous à SNDS et JMRP

Microsoft propose deux outils gratuits à avoir avant de demander quoi que ce soit :

  • SNDS (Smart Network Data Services) : montre pour chaque IP combien d'emails Microsoft accepte, le taux de plaintes et si une IP touche des pièges à spam. La couleur verte, jaune ou rouge est le meilleur indice de ce qui se passe.
  • JMRP (Junk Mail Reporting Program) : vous envoie une copie de chaque email qu'un utilisateur d'Outlook signale comme spam, pour désinscrire les plaignants et voir quelles campagnes génèrent des plaintes.

Les rapports JMRP arrivent au format ARF. Collez-les dans l'analyseur de plaintes pour savoir qui s'est plaint et de quelle campagne.

Demandez le retrait étape par étape

  1. Ouvrez le formulaire d'assistance aux expéditeurs d'Outlook.com (Sender Support, sur olcsupport.office.com). Si le rebond vient d'une entreprise qui utilise Microsoft 365, le portail est sender.office.com.
  2. Indiquez l'IP bloquée (ou la plage), votre email de contact et collez le rebond complet avec son code.
  3. Expliquez en quelques lignes ce que vous avez corrigé, par exemple : « nous avons nettoyé la liste, configuré DKIM et réduit le volume ».
  4. Répondez à l'email automatique que vous recevrez : il demande généralement de confirmer la demande.
  5. Attendez la réponse, en général sous 24 à 48 heures. Elle peut indiquer un retrait complet, un retrait « conditionnel » (vous êtes surveillé quelques jours) ou que vous n'êtes pas éligible.

Si on vous dit que vous n'êtes pas éligible, répondez dans le même fil en demandant une escalade et expliquez à nouveau ce que vous avez changé. Avec des données (SNDS au vert, peu de plaintes), c'est plus facile.

Après le retrait : ne pas y retourner

  • Augmentez le volume vers Microsoft progressivement, comme pour un warm-up : Microsoft est le fournisseur le plus sensible aux changements brusques.
  • Envoyez d'abord à vos contacts Outlook et Hotmail les plus actifs.
  • Gardez le taux de plaintes sous 0,1 %.
  • Consultez SNDS chaque semaine et surveillez les rebonds 4.7.650 : ce sont les premiers signaux.
  • Activez les alertes Telegram pour savoir si votre domaine entre sur une liste noire.

Checklist

  • ☐ J'ai lu le rebond et je connais mon code (S3150, 5.7.511, 4.7.650 ou 5.7.515).
  • ☐ SPF, DKIM et DMARC sont corrects et alignés.
  • ☐ L'IP a son propre PTR qui renvoie vers elle.
  • ☐ J'ai nettoyé la liste et retiré les inactifs.
  • ☐ Je suis inscrit à SNDS et JMRP.
  • ☐ J'ai demandé le retrait en expliquant ce que j'ai corrigé.
  • ☐ Je vais augmenter le volume vers Microsoft progressivement.
